## Phase 1: Data model and YAML generator
**Scope:** project scaffolding per ADR-0001 (SvelteKit, TS 6.x); an editor image `glance-editor:dev` that `dev/up.sh` runs; the versioned model schema (zod) for pages, columns, head-widgets, theme,
branding, and an initial widget set (bookmarks, group, split-column, docker-containers, clock, calendar, html, rss,
monitor, search). Also the "raw" widget type for anything else, the generator, and the pinned `glance` binary
inside the editor image. CI's sample config comes from the real generator.
**Acceptance criteria**
- [ ] Every structural rule in ADR-0009 (3 columns, 1–2 full, slim ≤ 2, no group/split-column in group) is enforced
      by the model, with a test per rule. Each invalid Glance fixture has a matching model-level rejection test.
- [ ] Placeholders `${VAR}`, `${secret:x}`, `${readFileFromEnv:X}` and the escape `\${X}` round-trip byte-for-byte
      through model → YAML in every string field (property test plus fixtures).
- [ ] Generated YAML for every sample model passes the pinned `config:validate` (in CI, with dummy placeholder values).
- [ ] CI's smoke job uses `scripts/generate-sample-config.sh` backed by the generator, not the copied fixture.
- [ ] The generated file starts with the "Generated by…" header (if ADR-0010 is accepted).
- [ ] No UI. No writes outside temp dirs.

## Phase 2: Import of the existing glance.yml
**Scope:** `glance config:print` → parse → model, with unsupported parts kept as raw blocks (ADR-0011); an import
report (JSON plus human-readable); a CLI/API entry point only.
**Acceptance criteria**
- [ ] Import → generate → semantic YAML equality with `config:print` output (ignoring comments, key order and quoting)
      for every valid fixture and for Glance's upstream example config.
- [ ] Placeholders are never resolved (a test asserts that no env vars are read during import).
- [ ] Unknown widget types and unknown keys survive the round trip unchanged.
- [ ] The import report lists pages, widgets, raw blocks, placeholders, dropped comments and include files.
- [ ] Glance's upstream example config (`test/upstream-example.sh`) passes the above.

## Phase 3: Persistence, Save pipeline, rollback (API only)
**Scope:** SQLite store and revisions (ADR-0002), migrations framework (ADR-0003), the Save pipeline including the drift
check, atomic write and `.prev` copy (ADR-0008/0010), and snapshots/export. All against the test Glance container.
No auth (ADR-0004), but mutating requests check the `Origin` header.
**Acceptance criteria**
- [ ] Save writes atomically into a directory-mounted test Glance, and the harness confirms the reload.
- [ ] An invalid model or YAML is never written. The live file is unchanged (test).
- [ ] Drift: a hand-edited file blocks Save until resolved (test).
- [ ] Restore creates a new revision. `glance.yml.prev` always matches the previous applied revision.
- [ ] A migration from a fixture v0 → v1 runs with a pre-migration snapshot. A newer-than-code DB refuses to start.
- [ ] Cross-origin mutating requests are rejected (`Origin` check, ADR-0004).

## Phase 4: Editor UI: pages, columns, theme, Save, history
**Scope:** implements Claude Design's handoff for the page/column editor, the theme/branding editor, the explicit Save
button with validation messages, the history/restore screen and the drift banner. Delivered via ADR-0012.
**Acceptance criteria** (finalised once the design arrives)
- [ ] Create, rename, reorder and delete pages. Add and remove columns, with the layout rules enforced *in the UI*
      (impossible layouts can't be made, and the reason is shown).
- [ ] Theme and branding edits, with a preview.
- [ ] No auto-save: closing with unsaved changes warns.
- [ ] Before/after screenshots in the PR for every screen. You do the QA sign-off.
- [ ] Accessibility: keyboard-operable, labelled controls (axe check in CI).

## Phase 5: Editor UI: widgets and bookmarks
**Scope:** add, remove, reorder and move widgets between columns; forms for the Phase 1 widget set; the
bookmarks editor (groups, links, icons); groups and split-columns; a read-only "Advanced" view for raw blocks.
**Acceptance criteria**
- [ ] Each supported widget can be created and edited without YAML, and the generated output validates.
- [ ] Group/split-column nesting rules are enforced in the UI.
- [ ] Raw blocks are displayed and preserved across edits of neighbouring widgets.
- [ ] Placeholder values are shown as placeholders (never resolved), and are editable as text.

## Phase 6: Docker container visibility
**Scope:** socket proxy (ADR-0005); the precedence test (ADR-0009 #15) in CI with throwaway labelled containers;
a container list and a visibility toggle UI that writes to the `containers` map.
**Acceptance criteria**
- [ ] The precedence of the map vs labels is tested and recorded in a new ADR. The UI reflects the result.
- [ ] The proxy allows only `GET /containers/json` (and its defaults). A test shows `POST` is refused.
- [ ] Without a proxy, the free-text fallback works and shows a warning.

## Phase 7: Packaging, deployment and go-live (new stack on Unraid, then cutover)
**Context (clarified 2026-10-13):** this project ships a **new stack** that replaces the current Glance. The current
Unraid Glance is never modified. Its config is only read once, for the import.
**Scope:** the release image; Unraid deployment for the new stack: Glance pinned to `/glance.version` with a
**directory** config mount, the editor, and the socket proxy (deployment format, Unraid templates vs compose plugin, decided
in an ADR at the start of Phase 7); runbooks (install, upgrade, backup/restore, emergency `.prev` restore, cutover and
fallback). Then the import of the current config, side by side on other ports, a comparison, and cutover (you stop the
old container; it stays as a fallback). Finally the `v1.0.0` release PR.
**Acceptance criteria**
- [ ] The install runbook is followed by you on Unraid. Claude does not touch the host.
- [ ] The new stack runs side by side with the old Glance, and the imported dashboards match (your sign-off).
- [ ] The cutover and fallback (restart the old container) are both rehearsed.
- [ ] A rollback rehearsal on the test container: restore a revision, and restore `.prev` by hand.
- [ ] The release notes are approved by you.

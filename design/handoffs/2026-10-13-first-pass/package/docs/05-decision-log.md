# Every UX decision in this pass, approved

Reviewed by the owner on 2026-10-13. Approved decisions are final for implementation. Decided rows were open topics; the owner's choice is written under the status and overrides any default in the Decision column.

| Structure and navigation | | | | |
| D-01 | Three sections — Pages, Theme, History — plus one global Save bar. | A tree of the whole YAML; one long form; a home screen of tiles. | Matches how Glance is structured; keeps Save in one place regardless of where you are. | Approved |
| D-02 | Pages in a left rail on desktop; page select in the top bar plus bottom tabs on phone. | Page tabs across the top, as Glance does; a hamburger drawer on phone. | Tabs crowd and wrap as pages grow; a drawer puts page switching two taps away. | Approved |
| D-03 | Layout edited on a schematic: real column order and sizes, small columns narrower, page width as frame width. Not to scale. | Pixel-accurate rendering of widgets; an outline list only. | Shows the structure you are changing without needing widget data; an outline hides the column relationships. | Approved |
| D-04 | Widget settings in a right-hand inspector on desktop, full screen on phone. | A modal per widget; expanding the card in place. | Modals hide the layout you're arranging; in-place forms don't fit in a small column. | Approved |
| D-05 | Nested widgets (group, split-column) edited one level at a time in the same inspector, with a Back link. | Nested cards drawn inside the column; a separate screen per container. | Deep nesting is unreadable at small-column width; one inspector keeps one mental model. | Approved |
| D-06 | Phone layout chosen by the editor's own width (under 760 px), not the viewport. | Viewport media queries. | Same rule the design system uses for Settings; works when embedded at any width. | Approved |
| Page layout rules | | | | |
| D-07 | Glance's column rules are enforced by disabling invalid choices, with the reason shown next to them. | Allowing anything and failing at Save; silently fixing another column. | An invalid layout never exists in the draft, and nothing changes that you didn't touch. | Approved |
| D-08 | A new column is added as Small. | Asking for a size on every add. | Small is always valid under the rules; one less step. | Approved |
| D-09 | Removing a column moves its widgets to the neighbouring column, with Undo. | Deleting the widgets with it; refusing until the column is empty. | No silent loss, no forced busywork. | Approved |
| D-10 | The last page can't be deleted and the only full column can't be removed or made small. | Allow it and report at Save. | Both would produce a config Glance rejects. | Approved |
| Widgets | | | | |

| D-58 | “Cache” is shown as “Refresh data every” (number + seconds/minutes/hours/days) and only on widgets that fetch data and let you change it. | D-12 | YAML escape hatch per widget as an override: applying it switches that widget to YAML mode and the form goes read-only until you discard the override. | Live two-way sync between form and YAML; one whole-file YAML editor. | Two-way sync is where unknown keys, comments and \${VAR} references get lost. | D-13 | Three dedicated sections inside the generated form: Bookmarks groups and links, Docker containers, and container children. | Making the generic object-list editor handle them. | Bookmarks are groups → links → icon; generic nesting that deep is unusable on a phone. | D-14 | Unknown widget types and unknown keys are preserved and editable in YAML. | Dropping or rejecting them on import. | Glance versions add properties; the editor mustn't destroy what it doesn't understand. | Approved |
| D-15 | Every widget card and column header has a visible grip. Desktop: drag the grip to reorder widgets within a column, move them to another column or the head strip, or reorder columns; an accent line shows where it will land. | D-16 | Card actions appear only on the selected card. | Action rows on every card; a “…” menu. | Small columns stay readable; no extra tap behind a menu. | Approved |
| D-17 | Deleting a widget, link, group or column is immediate with an Undo toast. Deleting a page asks first. | Confirm dialogs for everything; no undo. | Everything is draft until Save, so undo is cheap; a page is the one large loss. | Approved |
| D-18 | Add widget is a searchable list with a category tag; types not allowed in the target are disabled with the reason. | A category grid; typing the type name. | Search is fastest for 28 types; disabling teaches the group rule where it applies. | Approved |

| D-62 | Default Pixabay mode is “Keep a rotating set”: pick categories, how many to keep ready (10 / 20 / 40) and how often to swap them (daily / weekly / monthly / never). | Save, validation and history | | | | |
| D-26 | One draft for the whole config; explicit Save; a live count of changes and a list in Review. | Autosave; saving per page. | Each save reloads Glance and clears its cache, so saves should be few and deliberate. | Approved |
| D-27 | Save runs the editor's schema check, then Glance's config:validate on the draft, then writes. If either fails, or the validator can't run, nothing is written. | D-28 | Problems appear as a list (where, field, why, Go to), a banner until fixed, and a Fix badge on affected cards; Go to highlights the field. | Inline errors only; a toast. | Problems can be on another page or inside a group; a toast disappears. | Approved |
| D-29 | After writing, “reload confirmed” means Glance answered a request after the write. | Claiming the new config is live. | configuration.md documents no health or config-version endpoint, so a response doesn't prove which config is loaded. | D-30 | Every save stores a full snapshot as a numbered version. A file changed outside the editor is detected and stored as its own version. | A git repository; an undo stack only. | Snapshots are enough for one user and easy to restore; git could come later. | Approved |
| D-31 | Restore loads a version into the draft; it goes live only through Save. | One-click rollback that writes immediately. | Same checks for every write. Costs one extra step in an emergency. | Approved |
| D-32 | If the file changed on disk since the draft began, Save asks: keep the draft (the outside version is stored first) or load the file. | Silent overwrite; silent reload. | Either silent option loses someone's edits. | Approved |
| D-33 | Discard resets the draft to the live version, after a confirm. | No discard; discard per page. | A clean way out of an experiment. | Approved |
| D-46 | The draft is kept on the editor's server, so a draft started on the phone is there on the desktop. | Draft only in the browser. | You edit from both devices; a browser-only draft is lost or split between them. | Approved |
